# Wiki 图谱 v2 设计：手写引擎的抗压改造 + 折叠下钻

日期：2026-08-27
前置阅读：`docs/2026-08-27-wiki-graph-sigma-review.md`（Sigma 版评审结论：主线选手写版）
产物原型：`docs/prototypes/prototype-wiki-graph-v2.html`（单文件、零依赖、纯手写 SVG）

## 0. 一句话定位

证明"手写引擎"路线可以在千级条目下保持可用与可读：
性能靠**冻结唤醒 + 空间网格 + 增量渲染**三件套，可读性靠**折叠下钻**把"全量一屏"改成"展开哪部分画哪部分"。

## 1. 设计原则

1. **不换范式**：仍是单文件手写 SVG——DOM 结构、交互手感、视觉结果与 v1 连续，不引 vendor bundle。
2. **手感不变**：物理参数逐字沿用 v1（REP=9000 / REP_CUT=320 / LEN=110,170 / SPRING=.014 / GRAV=.004 / CLUSTER=.05 / 阻尼 .82 / 位移钳 ±12 / 半径档 7/10/13）。优化只改"邻居怎么找"和"DOM 怎么写"，不改力学本身。
3. **稳态零开销**：收敛即彻底停帧（没有 alpha 地板导致的永动微抖）；一切交互按需唤醒。
4. **确定性**：种子 PRNG 贯穿数据合成与初始抖动，同参数加载布局一致；不再劫持 Math.random。
5. **每个控件真实可用**：按钮点下去必须发生可见的事（评审沉淀的坑）。

## 2. 引擎改造四件套

### 2.1 冻结-唤醒模型（替代 v1 的永动 rAF）

状态机 `settled ⇄ active`：

- 启动：同步预跑 tick 直到收敛或超时护栏（quiet 判定：alpha ≤ 地板 且 全图平均位移 < 0.25 世界像素/tick；上限 2400 tick 或 3.5s），随后**取消 rAF 循环**。v1 的 alpha 永不低于地板也停不下来的问题就此消失。
- 唤醒源（各带 alpha 回热值）：拖拽节点 .25 / 松手回弹 .15 / 折叠展开 .35 / 手动重排 1.0 / resize 只重算焦点环+fitView 不唤醒模拟。
- active 循环每帧自适应批量 tick（预算 ~6ms）后统一 paint；再次 quiet 即回 settled。
- 副产物：SVG 版从此和 Sigma 版录屏里"画面自己走"的问题无缘——静止就是静止。

### 2.2 空间哈希网格：斥力+碰撞合并一趟扫描

- 格子边长 = 斥力截断半径 REP_CUT(320)，每点只查 3×3 邻桶；碰撞（半径和+10）在同一次邻桶访问内顺带完成。
- 布局发生在**虚拟像素画布** VW=1600·√(n/86) × VH=900·√(n/86)：面积随 n 线性放大 → 点密度恒定 → 每桶平均邻居数有界（几十个），单 tick 成本从 O(n²)≈10⁶ 次（n=1000）降到 O(n·k̄)≈几万次。
- 网格同时复用为**拾取索引**（见 3.2）。

### 2.3 增量渲染

- 每个 line/g 元素缓存上次写入的世界坐标；paint 时屏幕位移 <0.35px 的元素跳过 setAttribute。settled 时一次都不写。
- 画布平移/缩放只改 gWorld 的一个 transform，静态期内零元素级写放大；标签层单独处理（2.4）。

### 2.4 屏幕空间标签层 + 缩放 LOD

- 标签 `<text>` 移出变换层，放在屏幕坐标层（常量 11px 字号），位置 = k·pos+offset 逐帧算。这是必需变更：虚拟画布在全览时 k<1，沿用 v1"标签在世界层内缩放"的做法会缩成蚁字。边线用 `vector-effect="non-scaling-stroke"` 保持 1px 屏幕宽。
- LOD 三档随视口 k 切换：k<0.55 仅目录+聚合节点；0.55~1.15 加 deg≥6；≥1.15 加 deg≥2。hover/搜索命中强制显示不受档位限制。标签 DOM 惰性物化（千级时首批只建需显示的那部分）。

## 3. 交互改造

### 3.1 视觉连续性
配色、面板、tooltip、图例过滤、拖拽回弹等全部继承 v1。行为差异仅两处且都是有意为之：
点击空白**保留**详情面板（与 v1 的即关行为统一为保留）；双击空白 = 全览复位（新增工具）。

### 3.2 手动拾取替代 DOM 命中
pointermove 经逆变换求世界坐标后查网格近邻（阈值 max(r, 10/k)），O(1)。远缩放下小点的 hover 不再依赖浏览器对 3px 圆的拾取精度；hover 高亮改为邻接表直达边集合 O(deg)，替换 v1 的全边扫描 toggle。

## 4. 形态级设计：折叠下钻（千级的真正答案)

### 4.1 语义

- fold 视图中每个类目要么是**聚合球**（半径 ∝ √成员数，带成员计数与类目名常显标签），要么处于**展开态**渲染全部真实成员。
- 目录菱形恒为个体；目录↔类目结构边在折叠时映射为 目录→聚合球 细线；两个折叠类目间的引用边去重为聚合间淡线；展开区域内边缘照常画。
- 点击聚合球=展开该类目（成员从球心位置起排，唤醒 0.35 短收敛）；再次点击聚合区入口/面板按钮=折叠回去。
- 顶栏切换 平铺(flat)/折叠(fold)：世界重建但坐标承接（fold 进入时聚合球取成员质心），保证切换前后视角大致不丢。

### 4.2 默认策略
真实数据默认 flat（证明确实零回归的一屏），?n≥300 的合成压测默认 fold；记住用户上次选择（localStorage，try/catch 包裹 file:// 场景）。

### 4.3 搜索联动
查询能命中某折叠类目内成员时，该聚合球描金环并在标签尾部显示"·命中 N"；点击它即展开看细节。展开区域内的非匹配项照常淡化。

## 5. 规模验证方案

### 5.1 合成压测数据
`?n=<int>`：以真实 82 条目为种子骨架——11 个类目的真实 hub 与两枚目录节点保留，其余按真实类目权重生成成员（标题/tags/summary 由各类目真实 tag 词表组合、序号保证唯一、类型按 pitfall/note/reference/rule 加权），边按"挂 hub + 同类互引 p≈.22 + 跨类 p≈.05"生成。确定性和可读性都够评审用，文件体积只有几 KB。

### 5.2 HUD 指标（?bench=1 或 ?n 自动显示）
| 指标 | 定义 | 目标 |
|---|---|---|
| 预跑布局 | 语料就绪 → 首次 settled 冻结的总耗时 | n=1000 < 1.5s |
| 活跃均tick | active 期间 simTick 平均耗时（滚动均值） | ≤8ms@1000 |
| 稳态 | settled 后字面显示"冻结·无每帧循环"，并统计唤醒次数 | 稳态 CPU≈0 |
| DOM | 当前视图元素数 | 2000 节点 <1.5 万元素 |

### 5.3 分档触发路线（何时做什么，避免过度工程)
- ≥300 条：启用标签 LOD 与惰性物化（原型已内置，届时只是数据到位）。
- ≥800 条：默认 fold 视图上线。
- ≥3000 条：绘制层换 Canvas 2D 整帧重绘（只换 paint，引擎不动）。
- >1 万：再议 WebGL。

## 6. 已知取舍与风险

1. 标签改屏幕层后，深度缩放时字号不再随世界缩放——这是有意的（可读性优先），代价是与 v1 在极限缩放下的观感不同。
2. fold 的聚合间淡线可能在高引用密度时显乱；若观测到，降级方案是隐藏跨聚合并完全依赖展开查看。
3. 合成数据的度分布比真实 wiki 平缓（hub 度数不会到 17），极端 hub 拓扑的压力 case 另用 ?seed 扰动覆盖，不做专门构造。
4. 未做形态过渡动画（展开瞬间是短收敛的弹性感，无 tween）；评审确认交互语义后再投资视觉打磨。

## 7. 测试钩子（延续既有约定）

`?n=` 合成规模 / `?view=flat|fold` 强制视图 / `?bench=1` HUD / `?q=` 预填搜索 / `?seed=` 换合成种子 /
`?open=<类目>` 折叠深链展开 / `?dbg=1` 拾取调试 / `?probe=1` 布局数字探针。均作用于本文件独立验证。

## 8. 实现与实测勘误（2026-08-27 浏览器回归后补记）

原型落地 `prototype-wiki-graph-v2.html` 后相对本文前述内容的修正与实测（IAB/Chromium，1280×720）：

- **碰撞语义修正**：初版曾把碰撞并入斥力趟导致簇松散；已恢复 v1 的"积分后独立碰撞趟"（复用同一张网格），
  真实 86 数据簇恢复紧凑贴珠。
- **标签基线**：≤150 实体时直接沿用 v1 的 deg≥3 常显（LOD 不参与）；>150 时按缩放三档收紧、
  但恒亮全图度数前 18 的 hub（评审 P0-3 的落地形式）。n=1000 全景下屏幕恒有 20 个命名锚点。
- **实测指标**：
  | 场景 | 预跑 | 稳态 |
  |---|---|---|
  | 真实 86 · 平铺 | <50ms，即刻冻结 | 冻结 |
  | 合成 400 · 折叠首屏 | **13ms** 冻结 | 冻结 |
  | 合成 1002 · 平铺全量 | ≈3.5s 触时间护栏后冻结（§5.2 目标 <1.5s 未达） | 冻结 |
  千级平铺未达标的两点结论：一是该形态本应由折叠默认规避（≥300 已自动默认 fold）；
  二是引擎侧后续如需追平，方向是实体状态改 Float32Array + 数字键网格已做一半，剩逐 tick GC 与
  对象属性访问开销。
- **新增钩子**：`?open=<类目>`（折叠深链展开，兼作展开路径确定性测试）、`?dbg=1`（pointerdown
  命中调试）、`?probe=1`（各类目质心/焦点/散布周期输出）。syntax 由 node --check 保证。
- **已知 Harness 差异**：自动化指针经宿主缩放管线存在坐标漂移（元素级 click 亦然），画布命中验证
  以 ?dbg 输出+真实浏览器人工点选为准；真实鼠标不受影响。

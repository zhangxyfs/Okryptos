# Wiki 图谱原型评审：Sigma 版 vs 手写版（录屏对照）

日期：2026-08-27
对象：
- `docs/prototypes/prototype-wiki-graph.html`（手写 SVG 版，下称"手写版"，对应录屏 手写.mp4）
- `docs/prototypes/prototype-wiki-graph-sigma.html`（Sigma.js 版，下称"Sigma 版"，对应录屏 sigma.mp4）

## 结论

Sigma 版在当前真实数据规模（约 82 节点 / 60 边）下，首屏构图、可读性、画面稳定性全面输给手写版；
而它为"千级节点"准备的全部工程复杂度在本图上没有产生任何收益。手写版 900 tick 预跑在几十毫秒内完成，
O(n²) 斥力每 tick 只有几千次比较，毫无压力。

**建议**：主线选手写版方案落地；Sigma 版作为大规模预案冻结参数搁置，除非以下两条之一成立——
1) wiki 条目规模预期上千；2) 需要 WebGL 级渲染或子图级联动能力。
若仍要继续 Sigma 路线，必须先完成 P0 三项再进入下一轮录屏对比。

## 录屏对照观察

对照两段录屏（sigma.mp4 / 手写.mp4）：

| 维度 | 手写版 | Sigma 版 |
|------|--------|----------|
| 首屏构图 | 中心两个目录菱形 + 类目簇环绕 + 放射结构边，一屏读出层次 | 节点如撒开的芝麻，簇间大片空白，中央几乎无锚点，放射结构不可辨 |
| 默认视野可读性 | hub 全程带名称、边清晰 | 节点缩成 3~5px 小点，引用虚线隐形，几乎无词可见，需手动放大才能辨认 |
| 开场稳定性 | 预跑收敛后一次性 fitView，画面即刻定格 | 未操作的前几秒画面仍在缓慢漂移/变焦，点击目标会"跑" |

## 根因分析（代码定位均指 prototype-wiki-graph-sigma.html）

### 1. 布局管线叠了四层坐标系变换
FA2 预跑 → 焦点环聚拢 → 保形映射进虚拟像素画布（:223-225 VW/VH）→ 再叠手写 sim 活布局，
外加热 sigma v3 自己的归一化 framed 空间。任何一段的 bbox 异常都会传导成最终构图变形。
手写版从头到尾只有一个"页面像素"空间，没有转译损耗。

### 2. 焦点环半径取自 FA2 的 bbox 最长边
`enterCluster` 的 `R=E*0.40`（:165）与 simFocus 环的 `Math.min(VW,VH)*0.40`（:256）都以初布局 bbox 为基准。
FA2 结果横向散布一大时垂直方向被同比例撑开（y 向仅压到 0.85/0.8），环变得又大又扁——
这正是录屏里"内容贴边、中央空洞"的直接来源。

### 3. 相机机制放大了布局呼吸
- sim 活布局永不冻结：alpha 地板 0.02（:139 floor）+ 恒定焦点引力，bbox 每帧微变；
- sigma v3 随 bbox 逐帧重算归一化（:420-422 注释自证"normalization 随 bbox 逐帧更新，视野自动跟随"），
  等于给微小抖动加了自动变焦镜头，"地面自己在走"；手写版视口固定，同样的呼吸肉眼无感。
- 相机 ratio 写死 1.06（:423）：归一化只保证最长边铺满，另一侧必然留白。

### 4. 标签策略在最需要的首屏失效
小节点 label 直接置空（:114），hub 还要过 `labelRenderedSizeThreshold`（:387）。
默认全景视野下大多数节点低于阈值，一个词都没有。手写版同样是 "isDir‖deg≥3 才常显"规则，
但布局紧凑、缩放档位合适（fitView k 可放大），标签全程可读。差异不在标签规则本身，在于布局给了它成立的条件。

### 5. 千级节点的工程投入是负资产
vendor bundle（web/vendor/sigma-graph.min.js）、Barnes-Hut、网格桶近邻、隔帧渲染、
9 个 URL 调参旋钮（it/r/g/sr/slow/c/a0/fl/ff，:128-141）、bench 探针、ff 快进钩子。
旋钮挂一排本身就说明调参难以一次到位——事实上没调到位。

### 6. 次要行为差异
- tooltip 错位：节点在活布局里持续移动，enterNode 抓的是进入时刻位置，节点继续游走 tip 就留在旧坐标
  （mousemove 只对已 hover 节点补位）；
- clickStage 点空白立即关面板（:545），与手写版"点空白保留面板"行为不一致；
- 拖拽后 pin+回热逻辑两者一致，无差异。

## 若继续 Sigma 方案：下一轮修改清单

P0（不修不进下一轮评审）：
1. 布局管线收敛为单空间：去掉 FA2→焦点环双重变换，直接以焦点环作初始位、手写 sim 作为唯一布局引擎
   （或反向：FA2 出拓扑后直接进 sim，删除二次聚拢相）。目标：整条管线只剩一次坐标映射。
2. 相机可控：按实际 bbox 计算比例（纵横比分别适配），布局稳定后解除逐帧自动跟随，
   只保留低频 re-fit 或手动 reset。
3. 首屏可读性：默认视野强制常显目录与 deg≥3 标签（forceLabel 绕过 threshold）；引用边设最小像素宽。

P1：
4. tooltip 锚定已 hover 节点的实时视口坐标（graphToViewport 每帧更新），或 hover 时冻结该节点位移。
5. 行为与手写版对齐：点空白是否关面板双方统一（倾向保留面板）。
6. 参数固化：视觉调参完成后把 URL 旋钮收敛为默认值，仅保留 bench/ff 测试钩子。

P2：
7. Barnes-Hut/网格桶/隔帧渲染等重优化仅在大规模形态（sigma-2k 变体）保留，标准形态裁剪以缩小维护面。

## 值得沿用的部分

两个版本都做对了、后续实现应保留的设计：
- 种子 PRNG 接管随机数，布局确定可复现；
- 类目焦点环构图（问题不在构图思路本身，而在半径来源与相机配合）;
- 测试钩子（?q/?sel/?hover/?ff/?bench）支持 headless 截图验证；
- 性能探针 ?bench=1 直接量化入场耗时与帧工作量。

## 验证方式

修改完成后用同一数据重拍两段录屏对比；headless 场景用 ?ff=N 同步快进 + ?bench=1 断言入场指标；
交互核对点：开场 3 秒静止观察漂移、全景标签可读数、hover 跟随、拖拽回弹、图例过滤。

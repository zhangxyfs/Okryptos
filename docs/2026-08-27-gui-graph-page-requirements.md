# GUI 图谱页需求（管理下新增"图谱"栏目）

日期：2026-08-27
状态：需求定稿（未排期实现）
前置文档：
- `docs/prototypes/prototype-wiki-graph.html`（**渲染与交互规范源**：本需求锁定的技术路线，
  纯手写 SVG 力导向、单文件零依赖；拖拽选中蓝框、悬停邻居淡化等已修复行为以该文件为准）
- `docs/2026-08-27-wiki-graph-layered-design.md`（同一路线的规模扩容预案：
  骨架常显 + 类目下钻 + DOM 懒挂载，R3 的解构方案即来自此文档）
- 注：仓库内另有 `prototype-wiki-graph-v2.html` / sigma 版等探索性原型，经评审**不作为**
  本次需求的实现基线，仅作备选参考。

## 0. 一句话定位

把 `prototype-wiki-graph.html` 的图谱能力从原型 HTML 搬进 Web GUI，成为左侧导航的一级栏目：
**按项目查看知识条目关系图，图上能定位、能下钻，条目能一键跳回管理页。**

## 1. 需求条目

### R1 左侧导航新增"图谱"栏目，位于"管理"下方

- `web/app.js:342` 的 `MENUS` 在 `manage` 之后插入 `{ key:"graph" }`，ICON/i18n 文案沿用现有模式
  （`t()` 词条中英双语，中文"图谱"）。
- 菜单路由沿用 `location.hash` 改写机制；token 注入/sessionStorage 兜底链路不变
  （`web/index.html` 既有约定），图谱页所有数据请求走统一 `api()` helper。
- 无项目时的空态与管理页一致：落引导提示，不渲染空图。

### R2 页面内可选择不同项目

- 页面顶栏左侧放项目下拉选择器（样式对齐"其他"页的项目下拉）。
- 数据源 = `GET /api/projects`（复用管理页同一缓存口径，按 last_update 降序，默认选中最近更新项目）。
- 切换项目 = 重建整张图（数据、布局、选中态全部重置）；选择不做跨页同步，
  与管理页的项目选择互不干扰。

### R3 数据展现当前项目的全部条目；条目量大时按"骨架常显 + 类目下钻"解构

数据范围：所选项目的**全部条目**（pitfall/note/rule/reference 四型全收），
不是只画 wiki 骨架——图谱的价值就在看踩坑条目挂在谁身上。

解构方案（采用 `2026-08-27-wiki-graph-layered-design.md` 为 v1 路线定的预案）：

1. **类目（category）= 条目一级分组**，聚合/着色的最小单位。口径沿用管理页树的类目分组
   （`groupEntries`/`catKeyOf` 同一套），保证图谱与管理页看到的分组一致。
2. **两级节点**：
   - 骨架层（常显）：目录条目（菱形）+ 高连接度条目（`deg >= 阈值` 的大球）+ 它们之间的边；
   - 叶子层（按需）：其余条目，初始不进 DOM、不参与物理模拟（是完全不创建元素，
     不是 v1 图例 `dim` 那种"淡化但元素还在"的做法）。
3. **下钻交互**：图例/类目簇点击 = 把该类目叶子节点创建进 DOM 并做局部收敛；
   再点收起 = 从 DOM 摘除但保留坐标，再次展开无需重算布局；顶栏有"返回总览"。
4. **自动降级阈值**：条目数 ≤400（阈值调试后定）走原型既有全量模式，行为与
   `prototype-wiki-graph.html` 完全一致；超过则自动进入分层模式。
   当前 OpenKnowledge 项目（86 条）在全量档，零感知。
5. **边的口径**（需要后端新契约，见 §2）：
   - struct 边：类目/目录归属关系（目录条目 → 其成员条目）；
   - ref 边：条目正文/tags 中的跨条目引用（现有 wiki 条目互引关系）。

### R4 右侧详情面板的关联条目，双击跳回管理页并定位

- 图谱页单击小球 → 右侧滑出条目详情面板（原型既有行为：标题/类型/tags/摘要/关联条目列表）。
- 面板中的**关联条目行双击** → 切换到"管理"页，打开该条目详情，
  且管理页左侧树**展开到该条目所在类目并滚动定位**到该条目行。
- 实现直接复用管理页现成的 `jumpToEntry(file, project)`（`web/app.js:1952`）——
  终端 search 命中行跳转走的就是它：展开项目手风琴 → 展开类目 → 覆盖懒加载计数 →
  选中条目 → `scrollIntoView` 定位，全套语义已验证。图谱页只需 `state.menu="manage"`
  后调用它。
- 交互坑预警（知识库沉淀）：全量重渲场景下原生 `dblclick` 不可靠，
  双击判定必须走 `dblClick(h, key)` 时间戳检测（`web/app.js:1002`），
  与管理页树节点的四处双击同模式。
- 单击关联条目行的行为：图谱内联动（选中对应节点、图面居中高亮），不跳页——
  单击留在图里探索，双击才去管理页改/看详情。

## 2. 数据契约（后端新增）

新增 `GET /api/graph?project=<名>`，一次返回整张图（当前量级几 KB，无需分页）：

```json
{
  "nodes": [{ "id": "<file 名，与管理页 entrySummaryJSON.file 一致>",
              "title": "...", "type": "pitfall|note|rule|reference",
              "tags": ["..."], "category": "<类目>", "summary": "...",
              "isDir": false, "deg": 3 }],
  "edges": [{ "source": "<file>", "target": "<file>", "kind": "struct|ref" }],
  "categories": ["..."]
}
```

- `id` 用条目 file 名而非标题——这是 R4 能直接喂给 `jumpToEntry` 的关键（它按 file 定位）；
- `deg` 后端算好（边端点计数），前端不再推导；
- ref 边从条目正文/元数据的互引提取，struct 边从目录归属提取；
  提取规则与 `ok wiki` 生成侧的目录口径保持一致；
- 鉴权走现有 token 中间件，无新安全面。

## 3. 验收标准

1. 导航"管理"下方出现"图谱"，进入后默认渲染最近更新项目的全量条目图；
2. 顶栏切换项目，图整体重建且布局稳定（确定性种子，同项目两次进入布局一致）；
3. 悬停节点：相连边橙色高亮 + 非邻居节点淡化（v1 已修行为，搬进 GUI 不回归）；
4. 拖拽节点/平移画布不出现文本选中蓝框（`user-select:none` 修复不回归）；
5. 单击节点出右侧面板；面板关联条目**双击**跳到管理页，条目打开且树滚动定位到该行；
6. 构造 >400 条目的项目自动进入分层模式：首屏只渲染骨架层，类目可展开/收回，
   展开后物理模拟只跑可见集，界面不卡死；
7. 搜索命中分层模式下未展开的叶子条目时，自动展开其所在类目并高亮。

## 4. 非目标

- 图谱页不做条目编辑（编辑在管理页，R4 的跳转就是为此服务）；
- 不做跨项目联合图谱；
- 不更换渲染路线（不引入 Sigma/G6/WebGL，不使用 v2 原型的冻结引擎/折叠球形态——
  规模超出分层预案能力时另行评审，届时再议）；
- 不做 4s 轮询实时刷新（首版进入页面时拉一次；条目变更后手动重进或后续再加失效重拉）。

## 5. 实现排期建议（非需求，仅供参考）

1. 后端 `/api/graph` 契约 + 边提取（独立于前端，可先联调数据）；
2. 图谱页骨架：菜单 + 项目选择器 + `prototype-wiki-graph.html` 的引擎与交互搬进 GUI 页面容器
   （力导向参数、配色、tooltip、图例、面板照抄原型，零依赖）；
3. 详情面板 + R4 跳转接线（`jumpToEntry` 复用）；
4. 分层预案（骨架/下钻/可见集物理/阈值降级）接入真实数据。

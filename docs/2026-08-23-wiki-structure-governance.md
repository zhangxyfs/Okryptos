# wiki 结构化治理：总览瘦身 + 演进历程滚动归档（方案一+二）

日期：2026-08-23
状态：方案已定稿（用户 2026-08-23 确认"方案一+二可以接受"），待落地 SKILL.md
涉及：`internal/setupx/skills/openknowledge-wiki/SKILL.md`（仓库分发源，go:embed 进 setupx，随 ok setup 分发到各 agent 技能目录）、`~/.agents/skills/openknowledge-wiki/SKILL.md`（用户级已安装副本）
关联：`docs/2026-08-23-manage-search-terminal-requirements.md` 需求 5（参考目录子结构即本方案的 GUI 呈现面）

## 背景

`架构总览` 与 `演进历程` 是"只增不减"型条目，项目越复杂正文越长。压力点：

- hook 注入只带 INDEX.md 的标题+summary，**注入预算不受影响**；
- 真正的压力：①AI 检索命中后读全文吃上下文；②embedding 对超长条目语义稀释（向量按整条目算）；③人在 GUI 翻阅体验差。

## 方案一：架构总览瘦身成"目录地图 + 指针"

- `架构总览`只写**稳定的顶层结构**：每个主题域一行（职责一句话 + 指向对应 wiki 条目的指针），总览本身不再承载易变细节。
- 细节下沉到**主题域条目**（按目录/主题域聚合：gui=internal/gui+web、daemon=internal/daemon+daemonx+cmd/okd、检索=internal/index+embed*、agentx、wiki、发布=installer+scripts 等，十来个条目；`fsx`/`procx` 级工具包不单独成条）。
- 主题域条目可带**"沿革"小节**（本模块自己的版本节点，三五条）——目录级历史细节随条目走。

## 方案二：演进历程滚动归档

- `演进历程`主条目只保留**近期里程碑**（近期 N 个 + 早期压缩成一行一段的简述 + 指向归档条目的指针）。
- 超阈值即归档：阈值定为**正文超 6000 字或里程碑超 25 个**（先到先触发），把最老一段搬入 `演进历程-归档（v1.0~v2.1x）` 式归档条目（同为 wiki 条目，可检索可读，不丢信息）。
- 里程碑跨目录是常态，**主线保持时间轴不按目录拆**；目录级历史由主题域条目的"沿革"小节承载。

## 目标结构

```
架构总览（目录地图，稳定，GUI 树中"目录+文件"双重身份节点）
├─ 子节点 = 主题域条目（含沿革小节），即 GUI 树中架构总览下直接列出的章节
演进历程（近期里程碑 + 归档指针）
└─ 演进历程-归档（老里程碑滚动归档条目）
```

## 落地面（SKILL.md 修改点）

openknowledge-wiki 技能增补写作纪律：

1. **全量流程**：按顶层目录/主题域出条目（盘点已有分层扫描，直接对接）；架构总览只写目录地图。
2. **增量流程**：按 `git diff --stat` 路径把变更**路由到所属主题域条目**重写；演进历程追加里程碑时检查阈值，超则先归档再重写。
3. **条目规范增补**：主题域条目格式约定（职责/怎么协作/沿革小节）；架构总览格式约定（一行一域+指针）；归档条目命名 `演进历程-归档（<版本段>）`、tags `wiki,历史`。
4. 同步两处：仓库分发源 `internal/setupx/skills/openknowledge-wiki/SKILL.md` 与用户级副本（改分发源后跑 ok setup 或手工同步）。

## 历史数据迁移

### 原则

- **全部走 `ok add --force` 正式写路径**（fsx 锁 + 索引/向量/INDEX 同步），不直接手改 `knowledge/` 目录文件。
- **迁移前必须导出备份**（GUI 其他页导出 zip 或 `ok export`）——knowledge 数据不在 git，备份是唯一回滚手段；回滚 = 删除归档条目 + 从备份还原。
- **幂等可重入**：归档条目已存在则 `--force` 覆盖更新；主条目已瘦身则跳过，重复执行不产生重复条目。

### 条目归位（零内容改动）

- 现有 20 条 wiki 条目（tags 含 `wiki`）自动成为章节——GUI 按 tags 归到架构总览子节点，**无需改写**。主题域归属映射：

  | 主题域 | 条目 |
  |---|---|
  | gui | Web GUI、GUI 终端面板与栏目布局 |
  | daemon | daemon 进程模型、系统托盘 |
  | cli | CLI 命令面与项目路由 |
  | agentx | 多-Agent支持（agentx） |
  | sidecar | Reasonix sidecar |
  | 检索与注入 | 混合检索与 SQLite 索引、hook 注入与强制检查链路、跨轮注入冷却 |
  | embedding | embedding 多服务与本地模型 |
  | 存储 | 条目模型与存储布局 |
  | 沉淀与分发 | 经验沉淀机制、项目 wiki 功能、setup 与技能分发 |
  | 发布 | 安装器与发布 |

- **例外规则**：wiki 标签但 type≠reference 的条目（如"Gitea/GitHub wiki 仓须先初始化才能 push"是 pitfall、"新功能新增落盘文件时须同步检查 backup 导出白名单"是 rule）按需求 5 归组优先级进 踩坑/规则 类目，**不出现在架构总览子节点**——章节归集 = wiki 标签 ∩ type=reference；wiki 标签对它们只影响 INDEX 的 Wiki 目录呈现。

### 架构总览重写

重写为目录地图（一行一域 + 指针）。重写前逐段核对旧正文：独有细节确认已存在于对应主题条目，缺失的先搬迁进对应条目再重写总览，不允许只删不搬。

### 演进历程切分

- 切点：**v2.15 及之前**搬入归档条目 `演进历程-归档（v1.0~v2.15）`（tags `wiki,历史`）；主条目保留 v2.16 起近期里程碑 + 一行早期简述 + 指向归档条目的指针（切点可按"6000 字/25 个里程碑"阈值微调）。
- **已知行为**：`add --force` 重写会把 `created` 刷成迁移当日、mtime 随之更新（本库 2026-08-23 的总览/演进历程重写已发生过一次）——迁移后这两条变成"最新"，需求 5 的 mtime 动态排序会把参考类目顶到最前，属预期行为，不算回归。

### GUI 侧（需求 5）

纯前端归组，**无数据迁移**；无 wiki 条目的老项目参考目录只显示"其他"，零感知。

### 执行时机

首次按新规跑 openknowledge-wiki 增量流程时自动执行上述迁移；也可按本节清单手动一次性执行。

## 验收

- SKILL.md 两处同步更新，全量/增量流程含路由与归档动作。
- 迁移执行后：架构总览为目录地图形态且旧细节零丢失（逐段核对记录）；演进历程主条目瘦至 v2.16 起，归档条目可检索命中老里程碑；20 条存量 wiki 条目归位正确、wiki 标签的非 reference 条目仍在类型类目。
- GUI 树（需求 5）参考目录下架构总览子节点即为各主题域条目，结构自洽。

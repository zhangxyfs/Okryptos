## 背景

GUI 管理页（manage 菜单）为左树（项目 + 条目 + 搜索框）右详情两栏布局。本次三项需求：一个配色 bug、一个搜索框能力增强、一个新栏目。

## 需求 1（bug）：草稿标识与批准按钮可读性

### 现状

- 草稿徽标 `.badge-draft`：`background:none; color:var(--draft-fg); border:1px dashed var(--draft-bd)`（`web/style.css:150`），即无底色的虚线灰边灰字（light `--draft-fg:#6b7280` / dark `#8a8f9c`）。与背景对比度低，有草稿时看不清。
- 详情页"批准"按钮（`web/app.js:1208`）用普通 `.btn` 样式，与"编辑/归档/删除"无视觉区分，不醒目。

### 要求

1. 草稿徽标改为**实底高对比**配色（建议琥珀/橙黄警示色系，与条目类型徽标的蓝/绿/紫色系拉开），light/dark 双主题各给一组变量（`--draft-fg` / `--draft-bd` 语义可改为实底背景色 + 文字色）。徽标出现位置：树条目行、详情页属性行（`.d-attrs`），两处同一组件同步生效。
2. "批准"按钮改用主按钮样式（实心强调色底 + 白字，类 `.btn primary` 语义），鼠标 hover 有明确反馈。
3. 验收：light 与 dark 主题下，草稿徽标与背景对比度肉眼显著；批准按钮在操作组中一眼可辨。

## 需求 2：知识条目搜索框支持命令

位置：管理页左树头部搜索框（`web/app.js:1001`，当前仅按标题子串 oninput 即时过滤）。

### 命令语法

```
[范围]/type <类型> [关键词]
[范围]/tag <标签> [关键词]
```

- **范围前缀**：`/` = 只在**当前展开的项目**内检索；`//` = 在**所有项目**中检索。无展开项目时 `/` 退化为全部项目，并在树区域给出范围提示（如"未展开项目，已在全部项目中检索"）。
- **`/type <类型>`**：类型值用代码中定义的英文值——`rule | pitfall | note | reference`（`internal/entry/entry.go:29`），另加 `draft` 表示"草稿条目"（`draft=true`，与 type 正交）。非法类型值回车后给出错误提示并列出合法值，不过滤。
- **`/tag <标签>`**：过滤 tags 中包含该标签内容的条目（子串匹配即可，与现有标题过滤同策略）。
- **尾随关键词**（可选）：命令后空格跟的关键词继续按标题子串过滤，与命令条件取交集。
- 普通文本（不以 `/` 开头）：保持现有行为不变（oninput 即时按标题过滤，跨全部项目）。

### 交互

- **命令下拉提示**：输入框内容以 `/`（或 `//`）开头时，输入框下方弹出命令下拉列表（浮层卡片 + 高亮行，GUI 自有样式，不抄袭任何外部产品的视觉）。列表项与行为：
  - 输入 1 个 `/` 时显示 **4 项**（两种斜杠范围都列出，**列表项文案带斜杠前缀**）：`/type` 按类型过滤（当前项目）、`/tag` 按标签过滤（当前项目）、`//type` 按类型过滤（全部项目）、`//tag` 按标签过滤（全部项目）；输入 `//` 时收窄为 `//type`、`//tag` 两项。
  - 继续输入按已输入字符前缀过滤列表（如 `/t` 剩 type/tag，`/ty` 剩 type）。
  - 选中/输入到 `type `（含尾随空格）后，下拉切换为提示合法类型值（rule/pitfall/note/reference/draft）。
  - 键盘 ↑↓ 移动高亮、Enter 选中补全、Esc 关闭；**鼠标必须可点击选中**（用 mousedown 抢在输入框 blur 之前触发，或下拉容器内不使输入框失焦）。
- 命令**回车生效**；命令解析中（未回车）不打断现有即时过滤的输入体验——输入以 `/` 开头时暂停即时过滤，回车或清空时恢复。
- 命令生效后，搜索框下方（或树区域顶部）显示一行当前过滤条件摘要（如 `全部项目 · type:rule · "超时"`），附"清除"按钮恢复无过滤。
- 空命令（仅 `/` 或 `//`）回车：显示可用命令帮助（/type、/tag 及合法类型值）。
- 过滤结果沿用现有树的渲染与懒加载；无命中时显示空态提示。

### 验收

- 输入 `/` 即弹出 4 项命令下拉（type/tag/全局 type/全局 tag），鼠标点击可选中；`/ty` 过滤到 type，↓+Enter 可补全；`/type ` 后下拉提示 5 个合法类型值。
- `/type rule`（有展开项目）只显示该项目 rule 条目；`//type draft` 显示所有项目草稿。
- `/tag go` 命中 tags 含 go 的条目；`/type pitfall 构建` 为交集。
- 非法命令/非法类型有可见错误提示，不产生误导性空结果。

## 需求 3：右侧区域新增"终端"栏目

### 形态

在管理页右侧区域新增一个"终端"面板，交互参考截图（chat 式 CLI）：

- **命令写法不带 `ok` 前缀**：用户只输入子命令及参数（如 `list`、`search 超时`、`capture auto`），前缀 `ok` 由系统隐式补齐执行；历史回显、chips、占位提示、帮助文本全部使用无前缀写法。
- 顶部到底部为**历史记录流**：每条历史 = 命令回显条（`>_ list` 样式，**执行状态文字直接跟在命令后面**——✓ 执行成功 / ✗ 执行失败 / ⏳ 执行中，占同一行不多占一行）+ 结果卡片（卡片只承载输出：按行单行截断 `...` + `title` 悬浮全文；失败卡片红边框；执行中不出卡片）。
- 底部固定**命令输入框**（占位提示如"输入命令，例如 list"）+ 发送按钮；Enter 发送。
- **终端输入框命令下拉**：**只要焦点在输入框就显示下拉**（空输入时显示全部命令），输入时按已输入首 token 前缀过滤；下拉**紧贴输入框上边缘向上展开（浮层覆盖式：盖住 chips 行与历史区，不挤压布局），高度自适应内容**（有多少项显示多高，**不允许出现空白区域**；仅当条目多到超出面板可用高度时才内部滚动）。列表项 = 命令名 + 用法 + **功能说明**（如 `search <查询>` 语义检索条目、`capture [propose|auto|interval <n>]` 查看/设置沉淀模式）；**高亮选中项一行显示不下时，文本自动走马灯横向滚动显示全文——单向循环式**（向左滚出后从头接续，循环播放；不做来回往返滚动；未高亮项保持省略号截断）。↑↓ 高亮、Enter 或 **Tab** 将高亮命令补全进输入框（下拉打开时 Enter 优先补全不发送）、Esc 关闭、鼠标可点击选中。**发送命令后下拉自动关闭**（露出历史区最新回显与输出），再次输入变化、按 ↑↓ 或重新聚焦时重新弹出。
- 输入框上方**命令快捷 chips**：只显示命令名（如 `list`、`search`、`doctor`），**不带用法说明**（用法在输入时下拉中给出）；点击填入输入框。
- 面板内独立滚动；**历史区显示本次会话所有已执行命令的回显与输出结果**（最新在底部，发送后自动滚动到底），历史不清空（会话级，刷新页面可清空）。

布局方案见原型三个变体（A 三栏 / B 右区 Tab / C 底部抽屉），评审后定稿其一。

### 命令范围（白名单）

执行 `ok` CLI 子命令子集（用户输入不含 `ok` 前缀，后端收到 args 后隐式以 ok 命令面执行）。建议白名单（定稿时可调）：

- 只读：`list`、`search <查询>`、`doctor`
- 常用写：`add`、`propose`、`approve <file>`、`archive`、`capture [propose|auto|interval n]`、`wiki <status|mark|base|diff>`、`on`、`off`
- **排除**：`hook` 及协议子命令（prompt/post-tool/stop/compact）、`daemon`、`extension-serve`、`gui`、`init`、`setup`、`index`（内部/破坏性或已在 GUI 有专门流程的命令）

白名单外命令返回"不可用命令"错误卡片，并列出可用命令（与截图的失败卡片形态一致）。

### 后端

新增端点 `POST /api/terminal/exec`，挂到 `internal/gui/api.go` 的 api 路由组（复用 `withAuth`）：

- 请求：`{ "args": ["search", "超时"] }`（参数数组，不经过 shell，杜绝注入）
- 行为：白名单校验 → 进程内调用 cli 对应命令（或直接 exec 同进程二进制），捕获 stdout/stderr，**超时保护**（建议 10s，超时 kill 并返回超时错误）
- 响应：`{ "code": 0, "stdout": "...", "stderr": "..." }`
- 工作目录：当前树中选中/展开项目的根目录；无选中时用 GUI 进程 cwd（检索类命令本就跨项目）

### 验收

- chips 点击填入命令、Enter 执行、结果卡片正确区分成功/失败。
- 白名单外命令有友好错误；`search` 等耗时命令不卡死面板（异步 + loading 态）。
- 终端面板操作不影响左树/详情的现有轮询与编辑态。

## 需求 4：顶栏 UI 配置按钮（栏目布局）

### 入口

- 顶栏右侧、主题切换与语言切换按钮**左侧**新增一个**图标按钮**（齿轮/滑杆类图标，无文字），tooltip"界面设置"。
- 点击弹出**模态弹窗**（居中遮罩层，Esc/点遮罩/取消均可关闭）。弹窗只收纳**纯 UI 相关设置**，不碰后端配置。

### 第一项设置：管理页栏目布局

- 管理页三个栏目——**条目树、详情、终端**——允许自定义所在位置：
  - 终端：可选**左 / 中 / 右 / 下**四档；
  - 条目树、详情：仅可选**左 / 中 / 右**三档。
- 位置语义：左/中/右 = 三栏横向排列的槽位（栏目的相对顺序由各自槽位决定）；终端选"下"时，终端占满页面**底部横排整条区域**，上方区域由树 + 详情两栏横向排列（此时树/详情可选槽位退化为左/右两档，或仍按左中右三档取顺序、空槽自动压缩——实现取简单者，原型演示其一即可）。
- **冲突约束**：同一时刻同一槽位只能有一个栏目。弹窗内已被占用的槽位**不出现在其他栏目的选项中**（直接不显示，而非置灰）。
- 默认值 = 现状：条目树=左、详情=中、终端=右。

### 保存与持久化

- 弹窗采用**勾选+保存按钮两段式**（沿用 GUI 开关类设置交互约定，不用 change 即存）：弹窗内改动先落在草稿态，点"保存"才生效；"取消"/关闭放弃改动。
- 保存后立即重排管理页布局，并写入 **localStorage**（UI 偏好属前端态，不入后端配置文件）；下次打开 GUI 按已保存配置渲染。
- 提供"恢复默认"按钮，一键回到默认布局（同样需点保存生效）。

### 验收

- 顶栏出现图标按钮，点击弹窗；终端可切到左/中/右/下并立即看到管理页重排。
- 冲突槽位不显示在选项中；保存后刷新页面布局保持；恢复默认可回到三栏现状。
- 布局变化不影响三个栏目各自功能（树过滤/命令、详情操作、终端历史与下拉均正常）。

## 需求 5：管理页树按类目分组（项目下子目录）

### 结构

每个项目展开后不再平铺条目，而是按类目子目录分组（空类目不显示）：

- **归档**（archived=true）、**草稿**（draft=true）、**注入**（mandatory=true）
- **规则**（type=rule）、**踩坑**（type=pitfall）、**笔记**（type=note）、**参考**（type=reference）

**类目顺序**：**草稿固定置顶，归档固定沉底**；中间类目（注入/参考/笔记/踩坑/规则）按**类内最新条目的 mtime 降序**动态排序——类目顺序随条目更新变化（mtime 已在 `entrySummaryJSON` 中，`internal/gui/api.go:364`，无需后端改动）。

**归组优先级**（多维重叠时只入一个目录）：归档 > 草稿 > 注入 > 类型。即归档条目只进归档目录，非归档草稿只进草稿目录，非归档非草稿的 mandatory 条目进注入目录，其余按类型。

### 参考目录的子结构（wiki 条目专属）

- **架构总览**：**目录+文件双重身份**节点——点击节点名直接在详情区展示其对应 .md 的真实内容；箭头/图标区可展开，**子节点直接是各章节 .md 条目**（Web GUI、daemon 进程模型等 wiki 主题域条目，**不再有"章节"中间目录**）。按标题精确匹配识别，无此条目则不显示。
- **演进历程**：同为**目录+文件双重身份**节点（2026-08-23 设计修订）——点名展示其索引内容；箭头/图标区展开，**子节点是版本段条目**（`演进历程（<版本段> <主题>）`，tags 含 `wiki` 且含 `历史`），按段标题首个版本号数值升序；条目识别同上，无此条目则版本段回落进"其他"。
- **其他**：真目录，收纳普通 reference 条目（无 `wiki` 标签者）。
- 参考目录内固定顺序：架构总览 → 演进历程 → 其他。
- 章节条目识别规则：tags 含 `wiki` 且不含 `历史` 且标题非"架构总览"/"演进历程"（含 `历史` 的为演进历程版本段）；带 `branch:` 标签的分支差异条目按当前分支过滤后排列在后。

该结构承接 `docs/2026-08-23-wiki-structure-governance.md`（wiki 结构化治理：总览瘦身成目录地图 + 主题域条目承载细节含沿革小节 + 演进历程索引化按版本段拆子条目）——架构总览的子节点即主题域条目集合，演进历程的子节点即版本段条目集合。

### 交互

- 类目目录行：单击 = 选中（高亮），双击 = 展开/收起；箭头/图标区单击直接展开/收起（类目间不互斥，可同时展开多个；项目级手风琴保留）；目录行右侧计数徽标显示类内条目数。
- **默认展开规则**：项目首次展开时**类目不全部展开**——有草稿条目则只展开**草稿**目录；无草稿则展开**类内最新 mtime 最大的那个类目**；其余类目收起（用户手动展开的状态会话内保持）。
- 归档目录默认收起，其内条目沿用 archived 淡化样式。
- **图标**：类目目录统一文件夹图标；**架构总览节点用文件夹图标**（体现可展开的目录身份）；**演进历程节点用自绘时钟 SVG**（同样可展开的双身份节点）。
- 与需求 2 搜索命令兼容：过滤生效时类目内只显示命中条目，空类目隐藏；过滤摘要条不变。
- 懒加载下沉到类目内（类目内条目 >N 时分批追加）。
- 树的拖拽分隔条、4s 轮询、编辑态保护等行为不回归。

### 验收

- 多维重叠归组正确（如 archived+draft 条目只出现在归档目录）。
- 草稿始终置顶、归档始终沉底；中间类目顺序随类内最新 mtime 变化（更新一条参考条目后参考类目上移）。
- 参考下：架构总览点名出内容、箭头展开直接列出章节条目（无"章节"中间层）；演进历程点名出索引、展开列出版本段条目（按版本号数值升序，v2.9 在 v2.10 前）；普通 reference 收进"其他"目录；无 wiki 条目的项目参考目录只显示"其他"。
- `/type rule` 过滤后仅规则目录有内容，空类目全隐藏。
- 树既有交互（拖拽/轮询/内联编辑）不回归。

## 非目标

- 终端不做真正交互式 shell（无管道、无环境变量、无 cd）。
- 搜索命令与类目分组不改后端——纯前端过滤/归组（数据已在 `MGMT.list` 全量缓存）。
- 不做历史命令持久化（localStorage 都不需要，会话级即可）。

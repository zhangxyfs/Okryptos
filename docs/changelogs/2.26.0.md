# 2.26.0 检索注入精度三件套

## 修复

- **短口语 prompt 误注入**：关键词通道新增覆盖度准入——虚词停用表只作用于准入计数，要求命中词元数达到 max(1, ⌈n × min_ratio⌉)（min_ratio 默认 0.25），纯虚词查询直接跳过关键词通道；修复「还是黑底的」这类短口语追问把无关条目注入上下文的事故。

## 新功能

- **LLM 相关性后置过滤**：检索候选可交给 LLM 裁决，只删不加；全程 fail-open——未配置 LLM、超时（默认 3s）或解析失败时保留原候选不降级。新配置节 `[retrieve.filter]`（`enabled` / `timeout_ms` / `max_tokens`）；`ok.log` 可按 `prompt filter` / `prompt coverage` 关键字过滤观测准入与过滤行为。
- **识别意图双「使用中」槽位**：`[llm]` profile 新增 `filter` 标记，新增 `active_filter` 槽——过滤专用 profile 优先，未设置时回退通用 active 档；GUI LLM 弹窗提供「识别意图」勾选与说明，可同时显示两个「使用中」徽标。
- **LLM 新增本地 ollama 档**：`kind=ollama` 本地推理、免 API key，`base_url` 留空默认 `http://localhost:11434`（自动补 `/v1`）；GUI 弹窗附推荐模型提示。

## 说明

- **波及面**：覆盖度准入对 `ok search` 与 GUI 检索同样生效；`ok propose` 的同域候选提示属召回导向，已明确豁免该门槛。
- 新配置节：`[retrieve.coverage]`（`enabled` / `min_ratio` / `extra_stop_terms`）与 `[retrieve.filter]`（`enabled` / `timeout_ms` / `max_tokens`），均有默认值，不配置行为不变——两者默认启用，filter 在未配置 LLM 时自动 fail-open 保留原候选。
- 若误注入回升，优先调 `[retrieve.coverage]` 的 `min_ratio`；LLM 过滤兜精度，二者可按场景独立开关。

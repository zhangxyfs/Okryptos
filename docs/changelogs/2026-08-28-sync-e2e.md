# 同步双设备闭环与冲突路径 E2E

日期：2026-08-28

新增 `tests/e2e/sync_test.go` 两个端到端用例（设计文档 §13 测试策略落地）：`TestSyncTwoDevices` 用两个临时 `OK_HOME` 模拟双设备——设备 A 写条目 → `ok sync init` 首推 → 设备 B `ok sync init` 克隆后能检索到该条目；A 再写一条 → B `ok sync` 拉取后同样可检索，且 `sync-status.json` 落盘 `conflict=false`。`TestSyncConflict` 验证冲突路径：双设备改同一条目 → 第二台 `ok sync` 报冲突退出、`sync-conflict.json` 落盘含冲突文件、本地修改不丢（仍在工作区冲突标记内）。测试以 `git init --bare` 临时裸仓当远端，不依赖 Gitea。

验收顺手补齐一处链路断点：`ok search` 此前直接查 kb.db 不做查询时同步，克隆/拉取（或手工改条目文件）后首次检索会查空库。现按 okd 契约"各消费方按需 mtime 增量 db.Sync"与 hook prompt 同口径，search 检索前先增量重建索引（embedding 不可用时降级为只同步 INDEX，关键词检索不被阻断）——设计文档 §2 的"mtime 重建链路"由此对检索消费方闭环。

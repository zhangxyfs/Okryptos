# GUI 同步面（P1-B）

日期：2026-08-28

同步功能接入 Web GUI。okd 新增七个同步端点：POST /api/project/sync（未 init 带 remote 则先走三情形初始化）、GET sync/status、GET sync/conflict-file（base/local/remote/working 四版本）、POST sync/ai-merge（LLM 合并，front matter 剥离取 local 版，只返回不落盘）、POST sync/resolve（me/theirs/merged）、POST sync/finish（校验全部解决后 rebase --continue + push）、POST sync/abort；/api/projects 项目对象带 sync 状态字段（fail-open）。管理页项目行新增同步状态点（绿/黄/灰/红四态）与同步按钮（即点即执行、转圈、toast 反馈——动作类纪律）。冲突解决页：卡片流（每冲突文件一卡，本地/远端片段并排预览 + Accept Me/Accept Theirs/Merge/AI 合并四按钮）+ 顶部钉住操作条（已解决 n/N + 完成同步（未全部解决禁用）+ 放弃本次同步），路由 #/sync-conflict?project=。三向合并编辑器：本地/结果/远端三栏，中间栏可编辑，冲突块按 git 标记解析采纳（rebase 期间标记上半=远端、下半=本地，严禁直译）；AI 合并预填中间栏由人确认。syncx 加冲突解决原语（ConflictFiles/ConflictVersions/ResolveFile/ContinueRebase/AbortRebase/MergeInProgress，三版本按用户语义映射 stage :2:=远端/:3:=本地）与 init 三情形编排下沉（InitForSync，cli/gui 共用）；config [sync] 加 llm_assist（off/local/server，空=auto，server 档本期 409）。全链路真 HTTP 测试覆盖冲突解决与放弃路径。服务端 okserver 管理面为后续阶段。

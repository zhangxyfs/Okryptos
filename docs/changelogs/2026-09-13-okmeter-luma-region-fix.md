# 2026-09-13 OkMeter：白底条目不可读根因修复（亮度采样区未生效）

## 问题

白色/浅色桌面背景下 dock 条目内容（液态玻璃等材质）不可读。此前已加"亮底时
形状内铺 60% 深底"兜底，但实机永不触发。

## 根因（三层叠加）

1. **采样区从未设置**：`init` 直建窗口不经 `applyWindowPos`，`setLumaRegion`
   从未被调用 → 采样恒退化为全屏均值（白色文件管理器只占屏一角时均值被稀释，
   实测全屏 ~0.46 vs dock 区域实际 ~0.98），亮底判定永不触发。
2. **液态玻璃 pill 项不更新亮度**：`liquid.cpp` 的 `lastLuma_` 只在圆球全折射
   路径（`fullGlass`，要求 `!pill`）赋值，胶囊/波形流等 pill 项恒为 0。
3. **阈值带脱离实测分布**：迟滞带 0.62/0.48 偏高（亮灰背景 0.5~0.85 落不进
   触发区），且 dark 材质用玻璃混合亮度（上限 0.32）判定，数学上永不触发。

## 修复

- `app.cpp`：init 建窗后补 `applyWindowPos()`；`setLumaRegion` 移到菜单/面板
  并集扩张之前，采样区取 dock 基础矩形（条目背后亮度才是判定对象）。
- 四材质 `backdropLuma()` 统一改用原始背景亮度，迟滞带收紧为 >0.45 深墨 /
  <0.35 浅墨（蓝壁纸 ~0.24-0.33 不误触，亮灰 ≥0.5 必触发）。
- `liquid.cpp`：深底判定前兜底刷新 `lastLuma_`（pill 路径也能拿到真实亮度）。

## 测试

- `build.bat` 编译 + 51 单测通过，/W4 零警告。
- 在线诊断（WM_APP+0x4C 转储）：采样区正确裁剪为 dock 可见区
  (rx=0 ry=369 rw=104 rh=294)，白窗测试 luma=0.978 → 深底出现、条目文字可读；
  蓝色壁纸 luma≈0.24 → 不触发，观感与此前一致。

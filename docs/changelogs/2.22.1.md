# 2.22.1 修复：引导页"安装后仍显示未接入"（HooksInstalled daemon 视角分裂）

- **问题**：GUI 跑在 daemon（okd）进程里，各 agent 适配器的 `HooksInstalled` 检测用 `os.Executable()` 作比对基准——okd 进程内它是 okd.exe，而安装/自愈写入的是换算后的 ok.exe，检测永远不匹配，点击「安装」成功落盘后仍显示「Hook 未接入」。三 exe 拆分（GUI 迁入 okd）后引入，claude/codex/deepharness/qoder/qoderide/reasonix/zcode 七个适配器全部中招。
- **修复**：agentx 新增 `currentCLIExe()`——`os.Executable()` + EvalSymlinks 后经 `daemonx.CliTargetFor` 换算（okd → 同目录 ok，其余原样透传，测试二进制不受影响），七个适配器的 `HooksInstalled` 统一改走它。与已修的写侧（GUI 注册、selfHealHooks 自愈）同一换算函数，读写视角对齐。
- **测试**：`TestCurrentCLIExePassthrough`（非 okd 进程原样透传）；okd 换算分支由 `daemonx` 的 `CliTargetFor` 测试覆盖；agentx 全量测试与全仓 `go test ./...` 绿。
- **升级注意**：无迁移——升级后打开引导页即显示真实接入状态；此前被误判的 agent 实际 hooks 配置是完好的，无需重装。

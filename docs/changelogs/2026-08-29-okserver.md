# okserver 服务端管理面（P1-C1）

日期：2026-08-29

新增服务端组件 okserver（NAS/Docker 部署，单机版零依赖）：internal/oksrv 管理面——SQLite 单文件存储（users/sessions/orgs/org_members/repos/audit/meta，照 index 包 WAL+ensureColumn 先例）、bcrypt 认证（golang.org/x/crypto，唯一新增依赖）、root 首启自动生成 32 位随机密码（写 <data>/INITIAL_ROOT_PASSWORD 0600 + 日志一次）、会话 token（下发明文、库存 SHA-256、30 天）、登录限流（每用户名 5 次锁 5 分钟）、管理操作全量审计。GitBackend 接口抽象 git 托管（CreateUser/CreateOrg/CreateRepo/AddOrgMember/CreateAccessToken 等），Gitea admin API 为首实现，fake 实现供测试与离线开发。HTTP API v1：meta/login（公开+限流）/me/repos/personal（幂等建仓+git token 首次下发）/users/orgs/members/repos/team/repos/audit（Bearer + root/admin/member 角色门控，root 不可禁用/不可被重置）。仓命名两层同构：个人 <user>/ok-<project>、团队 ok-<org>/<project> 全私有。cmd/okserver 薄主程序 env 配置驱动（OKSERVER_LISTEN/DATA_DIR/GITEA_URL/GITEA_ADMIN_TOKEN），不配 GITEA_URL 时 fake 离线模式并响亮告警。server/nas/ 部署包：docker-compose（双容器 + Gitea 治理四配置环境变量化）+ 多架构 Dockerfile（amd64/arm64，纯 Go 无 CGO）+ README（部署/升级/备份/TLS/资源底线）+ systemd 备选 + backup.sh。发布边界：三客户端构建路径（iss/build.py/nfpm）白名单天然不含 okserver（已 grep 验证）。E2E 起真 okserver 进程跑部署全链路（root 登录→建用户→建仓→权限负例→审计）。真 Gitea 容器全流程为手动验收项。本地接入（serverx/okd 转发/GUI 服务器页）为 Plan C2。
